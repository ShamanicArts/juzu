JUZU Rust visual parity audit Bun oracle vs Rust

Generated from isolated tmux captures at 164×75. This audit intentionally focuses on visible craft gaps, not backend capability. The Rust port is fast and functional, but the current surface still diverges from the original Bun/OpenTUI product in chrome, spacing, row rhythm, and diff treatment.

Primary correctionDefault to Bun-like smooth chrome; make boxes optional.
Diff correctionMatch Bun DiffView full-row bars and pane continuity.
Layout correctionReduce unused gaps, broken gutters, and heavy borders.
Process correctionVisual audit first, then one parity slice at a time.

Aesthetic backlog from this audit

Immediate slices

  • Add a Rust smooth chrome mode and make it the default for Bun parity; keep boxed chrome as an explicit toggle.
  • Replace diff box/panel treatment with a Bun-like full-pane surface, preserving details sidebar but reducing border scaffolding.
  • Make add/remove/context rows fill the full available diff row, not just the text span/glyph prefix.
  • Tighten graph/sidebar spacing to Bun row rhythm, especially blank lines, file summary placement, and details heading hierarchy.

Parity rules going forward

  • Do not claim visual parity from tests alone. Capture Bun and Rust side by side.
  • Do not invent diff visuals. Use src/tui/components/DiffView.tsx as the oracle.
  • Before changing chrome, prove whether Bun uses boxes, soft fills, or raw negative space in that state.
  • Every visual slice gets an HTML artifact, benchmark, tmux capture verification, and JJ commit.
